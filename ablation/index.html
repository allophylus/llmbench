Flash attention is a prefill multiplier and a memory saver — not a decode accelerator. With FA off, decode is within noise at 1.6k (30.6 vs 30.8 t/s) and a little slower at 27.7k (26.1 vs 28.7 t/s), while prefill at 27.7k falls from 698 to 117 t/s (17% of the FA-on rate). FA also allows the quantized KV cache: turning it off forces f16 KV, which is why that arm needs 24.7 GiB idle and peaks at 28.9 GiB instead of 20.4 / 20.6.
The production MTP + ngram preset is the slowest configuration at depth. It decodes at 13.3 t/s on the 27.7k-token prompt against 73.9 t/s for plain MTP — a 5.6× collapse — and it is also slower at short context (61.3 vs 92.7 t/s). ngram matching over a long, repetitive stream is pure overhead here, not a bonus.
Speculative decoding changes the long-form answer. Every speculative arm (MTP, DFlash n-max 7, DFlash default, MTP + ngram, DFlash n-max 3) matched the baseline on the short deterministic prompts — arithmetic, a list, a one-line function — byte for byte, but the open-ended 120-word prose answer differed in every one of them. It is not distribution-preserving on this build under greedy decoding: treat a spec-enabled result as a slightly different model, not the same model faster.

Long-context prefill and the cache

Cache verdict: the 566 t/s at 260K is genuine cold prefill. Re-measured on the same long-context model with a 257,190-token prompt, one cold request per run and cache_prompt:false: 570.8 t/s with cache reuse on, 571.1 t/s with cache reuse off — a spread of 0.1%, inside run-to-run noise. A single-slot run (573.5 t/s) does not change the picture. The result is not an artefact of prefix caching.

Limits of this comparison

What could not be measured
  • FA off without f16 KV. A quantized value cache requires flash attention, and the engine refuses to start otherwise. Every FA-off arm therefore runs f16 KV, so its VRAM is not directly comparable with the FA-on arms.
  • DFlash with FA off at 256K context. Not buildable: at 131k it already peaks at 31.68 GiB of 31.86 GiB usable, so a 256K f16 window does not fit.
  • MTP and DFlash together. Not buildable on this engine build: the two draft types cannot share one speculative slot, and MTP alone does not serve this model without ngram-cache alongside it. No combined number exists, so none is shown.

How it was measured

Method

One model, one engine build, every arm identical except the accelerator flags: Qwen3.8-27B-Q4_K_M on llama.cpp Vulkan build 11517 (commit 8a1a9b512). Context window 131,072 tokens; KV cache q8_0/q4_0 for the FA-on arms and f16/f16 for the FA-off arms. Decode = 400 generated tokens per request on a chat-template-rendered prompt, measured from the server's own timings block; prefill = prompt processing on the same request. Short prompt 1,603 tokens, long prompt 27,722 tokens (varied blocks), temperature 0, seed 4242, cache_prompt:false on every measured request, warm-up request discarded. “Answers = baseline” compares six fixed prompts (arithmetic, list, code, three prose lengths) byte for byte against the baseline arm.

Decode at 27.7k context is measured on a deliberately repetitive stream (a one-word answer repeated), which is the best case for a speculative decoder: read the speculative arms' long-context decode as an upper bound. The two non-speculative arms are unaffected. VRAM is idle-after-load and peak-during-request, sampled during the measurement.
