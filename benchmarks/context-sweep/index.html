Speed by context

Matched-context sweep: the server is restarted at each context size and the prompt is calibrated to that size, so prefill and decode are measured at the context they claim. Two cards, two tables — the numbers are never mixed.

One model per row, five contexts across: 4K, 32K, 64K, 128K, 256K. Each cell is prefill t/s (how fast the prompt is ingested) over decode t/s (generation speed once the model answers). How the context sweep was measured
  • Matched by construction. For each cell the server is stopped, restarted with -c <ctx>, and one prompt is built and calibrated with the model's own /tokenize to ctx − 512 tokens before it is sent. The 512-token headroom leaves room for the reply.
  • One cold request per cell. Temperature 0, top-k 1, prompt cache disabled, no streaming, a 64-token cap. The same request is used for every model and rung, so the columns are comparable down and across the table.
  • Validity checks, per cell. The context reported by the live server equals the rung; the -c argument is read back from the running process; the prompt lands within 0.2 percent of the target; the reply stops at the 64-token cap (finish reason length) — i.e. the model really did generate, not answer in two tokens.
  • GPU state. Every other model server is stopped before a cell and device memory is sampled at 1 Hz; the peak covers weights, caches for that rung, and the reply.
  • Failures are recorded, never substituted. Cells that did not measure are printed as such.
  • Read the columns as a curve, not a leaderboard. Part of the run shared the card with another job, so absolute prefill rates carry roughly ±5 percent extra noise; rung-to-rung ratios within a row are the reliable signal. Decode degrades with context on every model, but the size of the drop is a property of the model and its cache settings.

Source: benchmarks/ctx-sweep/ in the source repo — one JSON per model plus a combined sweep file, all cells checked in. Measured 2026-11-08. Rendered from those files by scripts/sweep_data.py.

How to read this

Every cell is one cold request per model per context: temperature 0, cache_prompt:false, no stream, and exactly 64 generated tokens (a fixed continuation prompt, because these models otherwise end a turn after a couple of tokens, which cannot measure decode). Prefill and decode t/s are the server's own per-request timings; peak VRAM is sampled on the GPU at 1 Hz during the request.

The R9700 runs llama.cpp's Vulkan backend on an AMD Radeon AI PRO R9700 (32 GiB) without speculative decoding. The RTX 3090 runs the CUDA backend on an NVIDIA GeForce RTX 3090 (24 GiB) with Qwen3.8-27B's MTP drafter enabled, which lifts decode most on repetitive output and leaves general-text throughput lower than these numbers.

Full RTX 3090 quality results (GPQA, thinking on/off, chat, a generated browser game) are on the RTX 3090 (CUDA) page.
